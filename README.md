# dsh-mc-agent —— 让 DSH 里的 AI 真的去玩 Minecraft

在 [DeepSeek Harness](https://github.com/deepseek-ai/dsh)（DSH）里给 AI 一副**能动手的身体**：
进服、寻路、挖矿、合成、熔炼、存取箱子、战斗、看第一人称画面。
它不是在"描述"游戏，是真的在玩。

本仓库是 [whale-craft](https://github.com/yzi1b/whale-craft)（作者 yzi1b）的魔改版，改名 `dsh-mc-agent`。

---

## 设计理念

> **agent 理解意图、分发任务；本地脚本执行。**

这是整套设计的核心，也是和"让大模型直接调 API 操作世界"最大的区别。

### 为什么

大模型擅长的是**理解意图**：你说"帮我做个铁镐"，它知道这要挖矿、烧炼、合成，知道现在缺什么。
大模型不擅长的是**精细执行**：连续三十步点击、控制走路节奏、判断这一镐会不会掉下去。

所以把两件事分开：

| 角色 | 负责 | 不负责 |
|---|---|---|
| **agent（大模型）** | 理解意图、提需求、看进展、必要时干预 | 不算合成树、不控制走路、不记背包里每个物品 |
| **本地脚本** | 把需求拆成状态机、执行到完成、报告结果 | 不理解"用户想要什么" |

agent 说一句 `mc_craft {name:"iron_pickaxe"}`，本地脚本自己会算：
缺工作台 → 去附近找；缺铁锭 → 熔炼；缺铁矿石 → 挖；没镐子 → 先做木镐 → 缺原木 → 开箱子拿。
**这一整串 agent 一个都不需要知道**，它只要看结果。

### 落到代码上

- **agent 只看到"工具 + 报告"**：每个工具入队就返回，完成/失败主动报告。
- **本地脚本只看到"世界 + 队列"**：它不知道 LLM 的意图，只按当前条件推进。
- **两边通过任务队列对话**：队列是 agent 能看、能改的计划板。

## 本地脚本 = 可恢复状态机

每个"干活"的本地脚本（`collect` / `craft` / `smelt` / `chest` / `navi`）都是一个**状态机**：

```
phase: find → approach → dig → verify → pickup → …  → done
```

关键规则（用户 2026-10-25 定，写进开发说明当硬规矩）：

1. **任务在队列里是平级的**，没有父子、没有递归。
2. **条件不满足 → 往自己前面插一件事**，自己退回队列等它做完。
   ```
   队列：[craft 铁镐]
   craft 缺铁锭 → 插 collect 铁锭到自己前面
   队列：[collect 铁锭] [craft 铁镐]
   ```
3. **插队成功 = 自己挂起**，不存在循环。
4. **前置任务失败 = 条件不满足 = 直接报错**（不重试、不计数）。
5. **进度只存在 `job.state`**：断线、排队、被打断，恢复后从原状态接着走。

### 好处

- **agent 看得懂**：`mc_probe {what:"jobs"}` 能看到"现在做到哪、还排着谁"。
- **agent 能干预**：`mc_interrupt` 冻结/重试/跳过/取消（最后手段）。
- **不会死循环**：所有"缺东西"都是一次插入，插入失败有明确出口。
- **可恢复**：恢复时重进函数，靠 `job.state` 接着走。

## 能干什么

### 干活（状态机驱动的长任务）

- **合成 `mc_craft`**：只给"要什么 + 几个"，本地自己算合成链；缺料自动收集、缺工作台自动找/放/回收、缺中间产物自动补
- **熔炼 `mc_smelt`**：找/放熔炉、精确放槽（输入/燃料分开）、按数量耐心等烧完、取出、回收熔炉
- **收集 `mc_collect`**：优先翻箱子（整组拿），没有再挖；挖完等吸附、捡不到才插一次导航
- **存取箱子 `mc_chest`（两步）**：先 `action:"open"` 走到箱子旁、把**内容清单**回给你；
  想好之后 `action:"take"/"put"` + `items:[{name,count}…]` 一次多组存取
- **丢东西给玩家 `mc_toss_to`**：跟随到他身边、等他停下，再朝他丢（`mc_toss` 是朝方向的原语）
- **跟随 `mc_navi {player, follow:true}`**：pathfinder 的 GoalFollow，一直跟到他停下
- **导航 `mc_navi`**：寻路 + 兜底策略
- **建造 `mc_build` / 放置 `mc_place`**：按图施工、批量铺设、自动选料（三废石优先）

### 被动层（不需要 agent 出手）

| 被动工具 | 干什么 |
|---|---|
| **killa** | 敌对进 5 格：有武器→自动换武器+跳劈；没武器/苦力怕→远离；接管时停掉队列并报告 |
| **auto_eat** | 饥饿 ≤17 按 熟食 > 生食 > 腐食 吃一个 |
| **溺水/受伤/饥饿预警** | 剩 <5 秒每秒报；持续掉血算死亡倒计时；三档饥饿提示 |
| **边缘保护** | 绕过 navi 直接前进时，本地按 MC 公式算摔落伤害（含护甲/羽毛靴），预警"不会受伤/掉 x 颗心/会摔死" |
| **自动换工具** | 挖之前自动挑最合适的工具；没有就按 铁锭→石→木 降级补 |
| **背包预警** | 空格 ≤2 提示清理，避免捡不起掉落物 |

### 感知层（agent 怎么"看"）

| 类型 | 工具 | 看什么 |
|---|---|---|
| 原语（0~6ms，本地镜像） | `mc_self` / `mc_block` / `mc_blocks` / `mc_entities` / `mc_look` / `mc_look_at` | 自身状态、一格/一片方块、周围实体、视角 |
| 工具 | `mc_observe`（第一人称截图+三段式感知）/ `mc_map`（地形图/竖列图）/ `mc_probe`（折叠：背包/扫描/诊断）/ `mc_status` / `mc_events` / `mc_watch` | 画面、地形、背包、事件 |

## 装到自己的 DSH

前提：Node.js >= 22、DSH、一个能进的 Minecraft 服务器。

```bash
pnpm add github:blueziii/dsh-mc-agent
pnpm add mineflayer-pathfinder mineflayer-collectblock mineflayer-tool mineflayer-pvp mineflayer-auto-eat minecrafthawkeye
```

然后把 `"dsh-mc-agent"` 加进 DSH profile 的 `dsh.profile.bundles`，重启 DSH。

详细步骤（账户、MC 模式、权限隔离）见 [插件说明.md](插件说明.md)。
